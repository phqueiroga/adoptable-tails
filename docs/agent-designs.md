# Five-Agent Design and Assignment Alignment

The organisation contains exactly five agents in the mandatory order:

```text
Scout -> Harmony -> PawBuilder -> TailTalk -> ShelterLead
```

Each stage produces structured JSON that becomes the next stage's input. A protected evidence record stores the live-query metadata and every cumulative handoff.

## 1. Scout - Researcher

Scout interprets the adopter questionnaire and invokes the Supabase REST Data API during the Researcher stage. It analyses the current available inventory, essential constraints, preferences, patterns, and missing evidence. Its output is an opportunity brief and candidate pool, not a final recommendation.

- Assignment archetype: identifies the opportunity through data analysis and pattern recognition.
- External connection: **yes** - this is the agent with the required live tool/API call.
- Distinct output: opportunity, needs, constraints, candidate IDs, inventory patterns, and unknowns.

## 2. Harmony - Designer

Harmony receives Scout's brief and converts it into a matching and customer-experience specification. It separates hard welfare exclusions from preferences, defines explanation requirements, and describes the recommendation journey.

- Assignment archetype: creates the solution through creative problem-solving and design thinking.
- External connection: no; it depends on Scout's live-data evidence.
- Distinct output: design goal, rules, ranking priorities, experience flow, and success checks.

## 3. PawBuilder - Maker

PawBuilder receives Harmony's design plus scores calculated by deterministic application logic. It builds the tangible shortlist and recommendation-card specification without changing scores or inventing animal facts.

- Assignment archetype: builds the functional artefact.
- External connection: no direct external API; it uses cumulative live records already retrieved.
- Distinct output: up to three structured recommendations, build notes, and limitations.

## 4. TailTalk - Communicator

TailTalk turns PawBuilder's artefact into ethical, customer-facing recommendation cards, calls to action, and questions to ask the shelter. It explicitly avoids urgency, guarantees, and unsupported claims.

- Assignment archetype: attracts and engages customers through messaging and storytelling.
- External connection: no.
- Distinct output: headline, introduction, customer cards, transparency notice, and next steps.

## 5. ShelterLead - Manager

ShelterLead reviews the entire chain. It checks current availability, hard constraints, score integrity, evidence support, unknown disclosures, and customer wording. It may reject the result. When approved, it produces an executive summary, operational insight, and improvement actions.

- Assignment archetype: runs the business through leadership and orchestration.
- External connection: no new query; it validates Scout's timestamped live-query evidence and source records.
- Distinct output: approval or rejection, validation results, executive summary, operational insights, and improvement plan.

## Why this is more than five chatbots

- Roles have non-overlapping authority.
- Every output has a distinct JSON schema.
- Later stages receive earlier structured outputs.
- The deterministic score prevents the LLM from making untraceable numerical decisions.
- ShelterLead can reject work rather than simply summarising it.
- Each run records evidence suitable for screenshots and transcripts.

## Current marking risks

1. **Claude is not yet configured.** Until the secret is stored and a successful five-call run is recorded, the working-prototype gate is not met.
2. **GitHub Pages is not yet deployed.** The live public URL and eight-week availability requirement remain open.
3. **Iteration evidence does not yet exist.** Multiple runs, failures, prompt changes, and before/after evidence are needed for the highest bands.
4. **The personal reflection cannot be generated by AI.** The student must write this section in their own words.
5. **Current legal sources are still required.** The final rationale must cite current GDPR and EU AI Act material, including applicable transparency duties.
6. **The Communicator must remain visibly customer-acquisition oriented.** Recommendation copy, calls to action, and trust messaging should be shown in the prototype and evidence.
7. **Synthetic data must stay dynamically queried.** The submitted code and screenshots must visibly prove the live Supabase call; a live URL alone is insufficient.

The project concept itself is well aligned. The principal grade risk is incomplete evidence or deployment, not the pet-adoption use case.
